# GreyTheory AI × ChaseOS — Scope and Authority Policy

> **Status:** active policy for the Security Research Product Lane  
> **Mode:** local-only / repo-docs / toy-demo proof until explicit operator approval

## Hard boundary

GreyTheory AI × ChaseOS does **not** perform external security testing by default.

Blocked unless a separate explicit approval packet names the target, authority, scope, limit, and proof requirements:

- external scanning
- unauthorized testing
- live target interaction
- exploit publication
- vulnerability disclosure or outreach
- credential, token, or secret validation
- customer/prospect contact
- public claims that imply real-world findings

## Default allowed work

Allowed without additional approval:

1. Local repo/docs snapshot and architecture review.
2. Research/product boundary mapping.
3. Safe local toy/demo apps and fixtures.
4. Agentic-system defense demos against intentionally local examples.
5. Prompt-injection/authority-boundary checklists.
6. Defensive report templates and evidence schemas.
7. GitHub packaging, README updates, roadmap updates, and local proof notes.
8. Public-safe draft content that is **not posted** until approved.

## ChaseOS lane placement

GreyTheory AI × ChaseOS is placed under **Business + GTM** as a future business/product incubation lane, not as generic build infrastructure.

Reasoning:

- The lane should become a postable proof surface for ChaseInTech and ChaseOS.
- The repo should demonstrate credibility in agent systems, cybersecurity, and agentic-system defense.
- Commercial/public/security actions remain gated like other real-world business lanes.
- Technical implementation work can still route to build handoffs when a bounded implementation packet is ready.

## Authority checklist before any external action

Before any action outside local repo/docs/toy-demo work, answer:

| Question | Required answer before proceeding |
|---|---|
| Who owns the target/system? | Named owner or program |
| Is written authorization present? | Yes, with source/path |
| What exact assets are in scope? | Explicit list |
| What actions are allowed? | Exact verbs/limits |
| Are credentials, secrets, or PII involved? | If yes, special handling required |
| Is disclosure/outreach/public posting requested? | Requires explicit operator approval |
| What audit/proof must be produced? | Artifact path + verification |

If any answer is missing, the action stays local-only.
