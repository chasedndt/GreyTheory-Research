# Disclosure / Authority Checklist

Use this checklist before any GreyTheory action moves beyond local repo/docs/demo work.

## Authority proof

| Field | Required |
|---|---|
| Target/system owner | Named person, company, or program |
| Authorization source | Written scope, program page, contract, or operator approval artifact |
| In-scope assets | Explicit domains, repos, apps, IPs, accounts, or local fixture names |
| Out-of-scope assets | Explicit exclusions |
| Allowed action types | Exact verbs, e.g. review docs, run local fixture, passive read-only check |
| Rate/volume limits | Explicit limits if any external interaction is approved |
| Data handling rule | No secrets/PII stored; redacted evidence only |
| Disclosure path | Named contact/platform, if disclosure is approved |
| Public posting boundary | Exact copy and target channel/account must be approved |
| Audit artifact | Local path for proof and decision record |

## Default decision

If authority is incomplete, choose:

> **HOLD — local-only work may continue; external testing/disclosure/outreach is blocked.**

## Approval packet shape

```md
Requested action:
Target / owner:
Authorization source:
Exact scope:
Actions allowed:
Actions blocked:
Maximum rate/volume:
Sensitive-data handling:
Rollback/stop condition:
Public/disclosure target, if any:
Audit artifact path:
Operator approval needed:
```

## Non-negotiable reminders

- Emoji reactions are not approvals.
- A general discussion is not approval.
- Approval for a local demo is not approval for live testing.
- Approval for a draft is not approval to publish.
- Approval for one target/action does not carry forward to another.
